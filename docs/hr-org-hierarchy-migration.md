# 全系統組織欄位對齊（2026-11-12）

正式組織定義為 **總公司 → 事業部 → 事業處 → 單位**，**職稱**為獨立欄位。
「單位」可為課、組、室、中心，不等同「事業處」；原欄位 `dept` / `unit` 不可直接推斷完整四層階層。

## 本次前端修正

- 七大系統共用的 `Port79OrgHierarchy.getValue(employee,level)` 可讀明確組織欄位及舊資料；
  只有原 `dept` 值明確以「總公司／事業部／事業處」結尾，才當作該層顯示。
- 人資主表、搜尋、篩選與匯出分開顯示「總公司／事業部／事業處／單位／原部門／職稱」。
  由於資料未包含指定層級時，顯示「—」，不自動建立虛構人員歸屬。
- 各單位人數／職稱統計只依實際 `section` 或 `unit` 分組，不以舊 `dept` 填補。
- 舊人資 Excel 匯入的「部門」仍支援，但範本明確標示「原部門」。
- 共用導覽與操作說明改用一致的層級名稱。

## 尚需正式 Google Apps Script 後端與資料完成

現有 GitHub **未包含正式執行中的完整 Apps Script Code.gs**，不能把上述前端
視為雲端員工資料已遷移。需要先由主管核對組織清冊，再在雲端主檔及對應 API 完成：

1. 員工 `headquarters/division/office/section/jobTitle` 欄位可儲存與讀回；
   兼容舊 `dept/unit` 且不丟失員工 ID、權限、考勤號碼、在職狀態與歷程。
2. 組織選項與父子關聯應有穩定識別鍵，明確保存事業部所屬總公司、
   事業處所屬事業部、單位所屬事業處，並支援新增與移除。
3. 人資編輯／匯入與考勤、工時、排班、請假、效率、歷史資料的
   人員篩選及報表共享同一套歸屬資料，避免各系統重新猜測欄位。
4. 資料遷移前先備份目前員工主檔及歷史紀錄，提供遷移對照及差異報表；
   不自動猜測不明的原部門，不刪除歷史紀錄。
5. 用真實在職名冊及所屬組織核對人數、職稱、缺漏層級和跨系統統計，
   在正式系統對每個儲存動作做雲端讀回確認。

本次**沒有**修改正式 GAS、回填任何員工歸屬或重設原系統資料。
