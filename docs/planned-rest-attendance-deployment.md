# 正式考勤確認與原休假日預排加班

考勤日期右鍵的「查核完成」是正式確認入口。一般查看、切換模組、讀取考勤成功，不是正式確認，不得觸發取消。

前端先重新讀取正式班表；只有雲端回傳 `plannedRestAttendanceVersion: 1`，才送出 `confirmAttendanceDayAndReconcile`。舊 GAS 維持既有申報查核，明確提示預排自動取消尚未啟用。沒有新增同步按鈕。

後端必須同時驗證考勤、排班與加班管理權限，限制在三者交集的人員範圍。既有 POST 路由持有 ScriptLock；有人持有排班編輯鎖時，停止確認，不能搶寫。重新讀取正式月份與跨月相鄰來源、已受理待寫入打卡、刪除墓碑及人資身分；確認期間版本或打卡序號變更時停止。

僅日期已結束、原排例／休／國／颱有明確依據、仍為預排、沒有審核或請假代班關聯、整班確定完全無卡時取消。單邊卡標「打卡待核」；完整配對保留預排並核對加班區間內實際分鐘數，不自動核准或改動原換算時數。審核紀錄交管理員處理。正常工作日無卡保留原班，標缺勤／待核，不作休假、也不扣假額度。

取消保留 `plannedRestResolution` 的完整原申報、原假別、操作者、時間與原因，並沿用每月加班異動日誌的 PREPARED／COMMITTED 讀回流程。考勤確認另存 `P79_考勤確認_YYYY-MM`。沒有新增請假單或刪除原始打卡。颱獨立計算，不計入國。

## 更新現有 GAS

必須先取得目前正式 Apps Script 原始碼，再執行：

```sh
node scripts/apply-gas-planned-rest.cjs LIVE_Code.gs PATCHED_Code.gs
```

修補程式會核對必要函式位置，遇到未知版本或已套用版本停止；不部署、不寫入正式試算表。產物包含與前端相同的 V6 配對引擎、休假考勤證據及預排核對規則，避免前後端使用不同配對規則。先前 V66 可通過修補與完整語法檢查，但這不表示已核對目前正式部署版本。

更新既有 Web App 部署後，先在副本核對四種假別、單邊卡、跨午夜、已審核與正常工作日，再確認正式考勤日期。正式資料不應用來製造缺卡或加班測試。

## 首頁雙頁圖表

預設第一頁，沿用原 weeklyPeople 計算。第二頁讀正式核准請假與人資職稱，依天數降冪，取消及重複版本排除。完整跨月天數只取選定月份；單月半日保留小數，跨月半日以 approvedDailyDays／dailyDays 的每日核准分配為準。缺少每日分配的跨月半日及無法辨識的新舊重複版本列待核，不猜算。換月清除兩頁舊資料並回第一頁。沿用原圖表位置及高度；職稱較多時在圖內捲動。人員效率排行原五筆高度與捲動規則保留。
