# smart-punch 考勤與加班優先修正測試報告

日期：2026-10-11。候選版本：2026.10.11.V30-SEVEN-SYSTEMS。

## 修改內容

- Excel 比對以員工識別、上下班側別、90 分鐘時間區間及來源識別建立索引，保留既有配對評分及全域一對一排序，涵蓋跨日、缺上班與缺下班。
- Excel 補缺採增量寫入：既有資料不整月重寫，相同匯入不重複新增；人工改勤優先，實體 ID 重複時拒絕寫入。
- 補缺轉成 system-confirmed、重複副本清理，均先讀雲端、寫入，再重新讀回核對。待傳、寫入失敗、回讀逾時或同時修改時保留未確認 Excel 來源；再次核對可收斂已完成但回應逾時的寫入。只清理已確認的匯入比對紀錄，不刪除原始 Excel 檔案。
- 打卡佇列優先於管理修改與大量修補；送出前持久保存。舊回應不會刪除較新的修改，寫入回條不會跳過其他人的增量事件。
- 改勤當月回到主考勤表，歷史月份保留年度表路由。讀取依 Sheets 時區保存到秒，避免 GAS 與 Sheets 時區不同導致讀回時間錯誤。
- 加班管理重用相同考勤與可見員工的配對結果，資料或可見範圍變動時重新計算；減少頁籤初始化重複運算及不必要的下拉 DOM 更新。
- 七系統快取依登入者、權限範圍、GAS 位置及查詢條件隔離；寫入後防止舊讀取覆蓋快取，直接驗證讀取略過快取。修正人資打卡裝置旗標的後端操作與權限刷新。
- 保留同時新增的請假餘額回讀驗證、請假匯出、考勤日期預填與班表介面修改。後端部署檔包含敏感設定，未上傳公開 GitHub。

## 效能與仍有的限制

合成測試 2,700 個班次、30 人、90 天，候選評分由 243,000 次降至 2,700 次，兩邊得到相同的 2,700 個有效匹配。最新本機運算時間由 2,650.9 ms 降至 190.2 ms；此為合成資料測試，不能當成 Google 網路耗時或瀏覽器 CPU 百分比。

加班快取測試連續 20 次相同資料只做一次配對；原地改勤及員工範圍變動會重新計算。尚未量測正式瀏覽器 CPU 百分比，也未逐一完成七系統所有畫面操作。

真實隔離環境歷史年度讀取約 91.8 秒、歷史改勤约 45.8 秒，仍是後續優化項目；當月打卡／補缺已採主表與增量途徑。單次 Google 服務與網路耗時會變動，不承諾完全沒有逾時。
