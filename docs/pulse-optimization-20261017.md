# Pulse 診斷建議對照與第一輪優化（2026-10-17）

使用者提供 Pulse Web 效能診斷室作為優化方向。已透過 Sites 讀取目前網站原始碼（56a933604ed46b24114d0b95a4e9a4d878cffb77）。Pulse 是手動量測與自訂門檻工具，紀錄只保存在使用者目前瀏覽器；預設 8.4→2.1 秒等數字是範例，不是 smart-punch 實測。本次沒有修改或重新發布 Pulse。

## 建議與現況

| Pulse 建議 | smart-punch 證據／處理 | 驗證界線 |
| --- | --- | --- |
| 限制首屏及單次呈現資料 | 已有考勤表每頁 50 列與月份篩選；保留完整資料供其他頁面存取 | 既有 bounded-render 與月份檢視測試；不代表實際首屏耗時 |
| 減少重複讀取及不必要資料 | 本次將隔離管理版快取清單由 IndexedDB 全表 getAll 改成讀取目前使用者的七個 system key，結果只保留時間與大小等標頭 | 新測試證實讀七次、不用 getAll、不將完整 payload 保留在清單；IndexedDB 仍會對這七個值做 clone，沒有宣稱完全不讀其位元組 |
| 減少 CPU／記憶體累積 | 本次對隔離管理版前端記憶體快取加入 LRU：最多 12 份快照、依既有序列化大小估算合計 8 MiB，離開頁面釋放 | 不是整個 JS heap 的硬上限；畫面資料及瀏覽器其他物件不在此預算內。未量測 CPU 百分比 |
| GAS 批次處理與分段計時 | 找回私有 V47 後端候選檔；仍須核對實際部署與執行錯誤，沒有改寫或公開該檔 | 不能把候選 V47 當作目前正式部署。公開 ping 讀取逾時，尚未確認正式 API 版本 |

## 程式範圍

修改 assets/port79-data-cache.js，但新行為同時要求 P79ManagementTestMode=true 且登入角色為 admin/superadmin、punchOnly 不為 true；因此只有隔離管理頁啟用。正式管理頁與員工打卡模式保留原快取行為。沒有修改考勤寫入、配對規則、權限判定或補傳佇列；沒有新增輪詢。

移出記憶體的快照仍留在 IndexedDB，需要時讀回；超過預算的單份快照可從 IndexedDB 取得最新內容，避免保留同 key 的舊版。沒有刪除持久快照或未確認寫入。

預算使用快照原有 size 欄位（序列化 payload 大小）避免每次命中重複序列化；缺失或無效大小才重新估算。因此它是保守的工作集管理工具，不是瀏覽器實際 heap 量測。

## 新增測試

management-cache-budget 共 7 項通過：連續 30 個月份後仍受份數限制、LRU 保留最近檢視、8 MiB 估算預算、超大快照替換後讀到最新資料、離頁釋放而持久資料與待傳內容保留、正式／打卡模式行為不變、清單只讀目前使用者七個系統索引且不保留 payload。

同時重跑 seven-cache-queue 23 項及 management-link 13 項通過。GitHub PR 將執行完整 17 支測試程式。以上為本機 VM 及 IndexedDB 模擬；新行為尚未部署至實際瀏覽器驗收，沒有宣稱 CPU 或整體記憶體已下降某個百分比。
