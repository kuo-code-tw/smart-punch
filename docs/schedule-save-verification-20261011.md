# 排班儲存測試與正式部署紀錄 — 2026-10-11

隔離 Google Apps Script 與 Google Sheets 雲端測試：18/18 通過。正式既有 Web App 已由第 28 版更新至第 29 版，Google 部署畫面顯示成功。正式端部署後的 HTTP 健康檢查尚未取得成功回應，不能視為已驗證正常。

## 修正與部署

- 排班儲存維持 V5 的考勤月結隔離，保留原本的授權、月份驗證及編輯鎖。
- 修正 `p79ScheduleRecordSaveReceipt_`：保存回條後回讀 Cache/ScriptProperties；至少一處回讀一致才回傳 true。
- 呼叫端以該回傳值設定 `receiptConfirmed`，避免回條保存失敗仍宣告已確認。
- 正式部署使用既有網址與既有專案，第 29 版；保留執行身分及原存取設定。
- 沒有執行正式班表／考勤測試寫入、資料初始化或解除正式管理員鎖。沒有把測試入口、人工測試 session 或測試資料 ID 放進正式版本。
- 可回復部署版本：28。正式部署 source SHA-256：`bb6fe0fd95801c540c4bbde9be8f8998ad9ac6cd4352308827a9fa47def1beca`。

## 本機補充測試與驗證範圍

- 已部署的精確原始碼通過 JavaScript 語法檢查及 21/21 本機回歸測試。
- 本機測試包括 Cache 失敗、Properties 失敗、兩者失敗、靜默寫入遺失、回條到期及鎖權限；它們是模擬測試，不計入 18 項雲端測試。
- 逾時測試使用伺服器注入寫入前 9 秒／寫入後 12 秒延遲，瀏覽器期限 1.5 秒／2.5 秒。它驗證真實雲端執行與未知結果核對，沒有刻意讓 GAS 達到平台執行時間上限。
- 過期鎖測試是在測試專案注入過期時間；並行測試使用兩個人工授權管理員 session，沒有使用兩名真人 Google 帳號。
- 尚未驗證完整正式前端的登入、按儲存、重新整理流程；沒有用正式班表作測試。
- 部署後 `deploymentCheck` 的 Google 轉址頁回傳「目前無法開啟這個檔案」；一次重試回報 `net::ERR_BLOCKED_BY_CLIENT`。已確認 Google 部署成功，尚不能確認正式 HTTP 端點可正常服務。不能將此限制當作健康檢查通過，也不能據此斷言 GAS 程式失敗。

交付包包含正式第 29 版精確程式、兩輪雲端 JSON 紀錄、隔離測試 harness、本機回歸程式及部署／測試截圖。第一輪 JSON 的 pending 是當時狀態；第二輪補完逾時與並行項目，完整前端流程仍未驗證。
