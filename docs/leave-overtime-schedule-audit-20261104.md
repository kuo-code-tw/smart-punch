# 請假、代班、加班、排班核對與儲存調整（2026-11-04）

## 核對範圍

核對正式分支的請假頁、逐日新增請假、加班共用表單、工時加班儲存、排班加班儲存及跨頁更新介面。先閱讀現有 V80 GAS 檔案，後續透過已授權的公司 Google 帳號進入正式 Apps Script，核對第 94 版的部署 ID 與前端原網址一致，再以實際正式主程式進行修正並發布第 95 版。本次沒有以真實員工資料建立、刪除或修改任何請假／排班／加班紀錄。

## 應維持的資料關係

| 事件 | 正確關係與處理 |
| --- | --- |
| 核准請假、安排代班 | 請假 ID、請假人員、代班人員、日期各自綁定；安排代班不等於已出勤或正式加班 |
| 兩人代班、逐日不同人員 | 依每位代班者當日的正式班別提出建議，不能共用第一位或第一天的加班類型 |
| 加班申報 | 使用目前有效規則與換算、完整打卡、同筆正式班表及版本；保留後端版本／權限／關聯檢查 |
| 預排轉正式 | 沿用原申報 ID，依完整打卡核對；不能用另一筆 ID 蓋掉既有申報 |
| 只補登請假 | 同一筆已核准請假可直接確認；不修改既有代班、班表或加班 |
| 刪除單筆請假 | 本機待申報佇列只移除該請假 ID，不能清掉其他日期、其他請假單的待申報 |
| 其他頁面有修改 | 收到成功回條後通知重讀；編輯中延後，範圍／身分改變時不套用過期回應 |
| 其他裝置有修改 | 回到請假、排班、工時管理頁時重新讀取；30 秒內的重複焦點事件合併，不新增輪詢 |

## 確認與修正的缺口

1. 加班儲存原先可能依序讀設定、整月班表、個人出勤與班表，再 POST。改成同次點擊並行讀有效設定與個人／日期資料，三個儲存入口共用該次核對。快照僅保存在記憶體、限同物件單次取用且 15 秒有效；登入、來源、人員、日期、請假 ID 不符則重新讀取。寫入仍附正式 revision。
2. 儲存按鈕原先等多個讀取完成才停用。改為進入核對前鎖定；核對失敗可重試。核對期間內容改變則停止該次送出。有效換算內容改變也會擋下舊選項。
3. 請假頁／排班頁的加班寫入補齊實際出勤時段檢查，並防止新申報覆蓋其他 ID 的既有申報。工時頁保留原有預排轉正式、審核資料及實際打卡檢查。
4. 排班頁原先在收到寫入回條後還等待完整畫面重整，重整失敗會落入儲存失敗。現在核對回條後回報成功，畫面重整獨立執行。員工送出請假的後續重整也不再延長送出按鈕等待。
5. 每次請假儲存前的核對原先可能偷偷清理所有歷史孤立代班，再完整重讀。改為唯讀核對；既有明確清理功能保留，不在一般新增或只補登時執行跨紀錄清理。
6. 逐日新增原先只有整批成功才保存待申報清單，部分失敗後會遺失前面已成功日期。現在每個已確認代班即合併到清單，重試不重複，新增下一批也不清掉上一批。新佇列可在重開頁面後接續。
7. 原先以月份共用請假接續核對結果，但出勤資料實際上只涵蓋特定人員／日期。改為以人員、日期、請假 ID 區分，避免同月不同日錯用打卡資料。
8. 補上請假修改及排班儲存別名的成功通知。工時頁在沒有編輯／寫入中時自動套用目前月份的正式資料；優先採用與班表同次取得的請假資料。

## 測試

新增可執行的 VM 回歸測試，涵蓋並行核對、單次取用／過期退回重讀、身分／日期／請假 ID 變動、缺少 revision、連點、三個真實儲存 adapter、出勤不足禁止送出、既有申報防覆蓋、畫面讀取失敗不回滾成功、逐日部分成功後重試及只補登不寫既有安排。

擴充待申報測試以涵蓋同月不同日資料隔離、佇列合併與選擇性刪除；擴充管理同步測試以涵蓋別名、工時自動更新、編輯保護及不同裝置回頁核對。保留原有核准請假日期、代班推薦、預排轉正式、刪除／封存加班類型及人員權限測試。

## 尚未能由本次證明的部分

- 正式部署已核對並更新：第 95 版，健康檢查回傳 `2026.11.04.V95-LEAVE-OVERTIME-FAST`、`ok:true`。真實員工的寫入秒數與完整跨裝置業務流程仍未用正式紀錄測試。
- 逐日不同請假者仍需要每一天的請假 POST 及代班 POST，沒有假裝成一次原子交易。中途失敗會保留已成功項目及其待申報資料。
- 加班寫入保留正式班表核對、日誌及讀回確認；不跳過稽核以換取速度。已修正回傳 revision 與釋放寫入鎖的時序，使批次前端能使用正確的正式版本。
- 同源分頁通知不能跨裝置即時推送；本次新增的是回到頁面時核對，沒有宣稱兩台持續停留頁面的裝置能即時推播。

## 正式後端第 95 版修正與驗證

- 儲存請假及代班不再初始化無關的考勤、人資設定、登入紀錄等工作表；各功能仍確認自己的正式分頁。
- 保存單筆代班時，不自動清理其他歷史請假／代班，也不預先呼叫出勤核對；只有實際開啟申報才讀取出勤。
- 新增／更新代班只寫入目標列；相同內容重試不重寫。若同一請假有多列歷史資料，保留原先重整該請假資料的相容路徑。每次寫入都有讀回確認，權限、在職、部門、日期、已核准請假、代班衝突及排休條件均保留。
- 加班成功回條在 ScriptLock 內先完成正式班表 revision，finally 不再次改掉該 revision；所有版本更新完成後才釋放寫入鎖。
- 新增 `tests/gas-leave-save-fast.cjs`，以模擬工作表驗證 1,000 筆既有資料時仍只寫一列、重試不重寫、相同請假多列相容、衝突／未核准／無權限／錯誤排休皆不寫入、讀回失敗不回報成功、回條版本不會在 finally 被改掉。
- 實際編輯器的修改前全文與讀取時相同才寫入；修改後全文與準備版本完全一致，代班函式與離線測試檔案的字元數及校驗值一致。Google Apps Script 儲存及第 95 版部署皆成功，原正式網址未變。
- 此次程式碼補丁及套用腳本保存在 `backend/leave-cover-fast-save.gs`、`scripts/apply-gas-leave-save-fast.cjs`。腳本只接受已核對的正式程式片段，遇到不同來源或已套用版本會停止。
